## 1. Visual Identity Foundation

### 1.1 一句话视觉规则

**先让校园、人物与调查工具像一个真实可用的中国日常世界，再让灵异只破坏其中一条可信的秩序。**

### 1.2 支撑原则

| 原则 | 设计检验 |
|---|---|
| 正常先可信 | 当“更有氛围”和“更像真实生活”冲突时，正常阶段优先选择真实；没有可信的正常，就没有异常的重量。 |
| 异常要局部而准确 | 当“多做几个故障效果”和“只破坏一个关键线索”冲突时，保留后者；玩家应能指出究竟哪里不对。 |
| 现场先于界面 | 当信息卡片会遮住环境或替玩家解释线索时，把信息还给场景、声音和可交互物；UI 只负责操作与记录。 |
| 恐怖必须可读 | 黑暗、噪点和遮挡不能毁掉必要信息；危险可以不完整，但不能因视觉不可读而变成随机死亡。 |

### 1.3 Campaign 与 Prototype 的视觉关系

可继承的是冷静档案、克制暗红、中文旧建筑质感和可访问性经验；不可直接继承的是槐荫里门牌主线、鬼影视觉符号、七日倒计时和开局总部终端身份。

正式第一章的主角仍是学生，视觉入口必须从校园现场、个人手机和随身记录开始。只有主角后续真正进入官方体系，原创的行动档案界面才逐步出现。

## 2. Mood & Atmosphere

| 游戏状态 | 目标感受 | 光线与对比 | 主要承载物 | 节奏 |
|---|---|---|---|---|
| 事件前校园 | 熟悉、松弛、略带青春期克制 | 自然日光或普通教室灯，低至中对比，肤色和校服可辨 | 课桌痕迹、黑板、作业、走廊人流、手机消息 | 平稳，允许停留 |
| 周一晚自习 | 日常即将闭合前的安静 | 冷白荧光灯，窗外较暗，教室内部仍完整可读 | 作业纸、讲台、墙钟、半空走廊 | 测量感，轻微变慢 |
| 鬼域侵蚀 | 熟悉空间开始失真 | 黑绿阴影吞掉远处层次，近处保留手电或手机照明 | 消失的远端、重复结构、错误的声音距离 | 断续，留出判断 |
| 逃亡与验证 | 紧张但仍能思考 | 局部高对比；危险轮廓和行动出口必须可辨 | 门、楼梯、扶手、楼板、脚步与敲击来源 | 短促行动后强制观察 |
| 规则被证实 | 短暂确定感，不是胜利庆祝 | 一个局部恢复清晰，其他区域仍保持威胁 | 被验证的物件、方向变化、声音停止或转移 | 明确、克制 |
| 代价与失败 | 冷硬、不可逆、可复盘 | 降低综合色彩，不使用全屏红闪 | 留下的物证、人物缺席、行动日志与最后可见原因 | 突然收束，之后留白 |
| 档案回看 | 理性压住恐惧 | 冷纸色、深墨色和少量机构绿 | 时间、地点、来源、可信度和未解项 | 稳定、可逐条核对 |

### 2.1 恐怖强度曲线

- 正常阶段不能提前用持续故障、满屏暗角或恐怖音乐透支危险。
- 异常初现只改变一到两个感官事实，例如声音距离、楼层对应或光照边界。
- 高强度阶段允许更深阴影、局部拖影和音画不同步，但每次变化都必须对应当前状态。
- 失败后避免立即用大字和强音效覆盖现场；先让玩家看到导致后果的最后证据。

## 3. Shape Language

### 3.1 环境

- 正常校园以水平、垂直和重复模数为主：门、窗、瓷砖、楼梯段和课桌形成可记忆的秩序。
- 灵异不另造华丽几何体，而是错位、缺段、重复、尺度不一致或无法闭合的既有结构。
- 关键交互物必须在轮廓、留白或光照上与背景分离，不依赖发光描边。

### 3.2 人物

- 普通学生、教师和工作人员优先使用自然比例、生活化姿态和不夸张的服装差异。
- 缩略尺寸下通过发型外轮廓、校服穿法、随身物和站姿区分人物，不用 RPG 职业配色。
- 灵异存在首先破坏人的姿态、位置或运动逻辑，不默认设计成可正面战斗的怪物轮廓。

### 3.3 UI

- 档案与记录使用严格矩形、细分隔线、对齐列和明确层级。
- 现场操作使用贴近物体的文字动作和低干扰标记，不铺满圆角卡片。
- 灵异状态可让一条边、一个索引或一个坐标发生错位；不能让整个界面持续抖动。
- 原创识别符号采用“档案索引缺口”语法：一个规整矩形中缺失一小段纵向编号线。它只是项目原创图形语言，不模仿任何官方 Logo。

## 4. Color System

### 4.1 主色板

| 名称 | Hex | 用途 |
|---|---|---|
| 深墨黑 | #151817 | 主背景、夜间结构、正文深色 |
| 旧纸白 | #D8D4C6 | 档案底色、柔和高亮、可读文本 |
| 机构绿 | #24322E | 档案标题栏、低风险系统状态 |
| 水泥灰 | #70736D | 校园墙面、次级信息、普通环境 |
| 荧光旧黄 | #B6AA72 | 教室灯、时间感、待确认线索 |
| 干涸暗红 | #812B2B | 已确认危险、不可逆行动、死亡关联 |
| 鬼域黑绿 | #07110D | 鬼域远端与空间吞没，不用于长正文底色 |
| 冷亮灰 | #E6E4DC | 深色界面的主要文字和焦点边界 |

### 4.2 语义规则

- 暗红只表示已经确认的危险、不可逆选择或严重后果，不表示普通可点击。
- 旧黄表示待核对、时间相关或照明承载的信息，不自动代表奖励。
- 机构绿表示记录、归档和稳定系统状态，不等于绝对安全。
- 鬼域黑绿用于空间和照明变化，不单独作为“有鬼”的提示。
- 线索可信度不能只靠颜色表达，同时使用来源标签、图形状态和文字。

### 4.3 区域温度

- 正常校园：中性灰、旧白、木色和现实肤色。
- 晚自习：冷白灯与窗外蓝黑形成轻微温差。
- 鬼域：降低综合色彩，保留手电照亮区域的现实颜色。
- 旧后勤区域：当前剧情 PAUSED；只锁定“长期封闭、真实存在”的物质感，不提前为第一只鬼指定专属颜色。

### 4.4 色觉与对比

- 红/绿状态必须同时具备图标形状、文字和声音差异。
- 正文与背景以 WCAG AA 对比为最低目标；氛围层不得降低正文对比。
- 焦点状态至少同时具有两种提示：边界变化、位置变化、文字标记或声音之一。

## 5. Character & Entity Direction

### 5.1 普通人物

- 目标是“现实中可能同校的人”，不是偶像化角色立绘。
- 面部、校服和随身物保持时代与地点可信；具体年份尚未锁定时，避免用强年代标志替代考证。
- 情绪优先通过视线、肩颈、手部和人与人距离表达，避免大幅漫画表情。
- 白月光在事件前必须拥有自己的日常行为和空间位置，画面不能只把她当成发光目标或主角奖励。

### 5.2 主角

- 未锁定姓名、固定面貌和第一只鬼外观，因此当前只定义普通学生阶段的比例、服装与动作标准。
- 主角在场景中的可读性来自构图、相机关注和交互反馈，不靠特殊发色、徽章或超自然光环。
- 后续异化必须从具体灵异代价推导，不能提前设计通用“升级造型”。

### 5.3 厉鬼与异常人物

- 外形必须服务于其杀人规律和活动痕迹；先确定规律，再确定实体细节。
- 不使用血条、受击闪白、战斗待机或 Boss 登场姿势。
- 恐怖来自“不符合人的存在方式”：错误的静止、缺少呼吸、位置不连续、衣物与环境没有同样的物理反馈等。
- 第一只鬼当前 OPEN / PAUSED，本节不能暗示白瓷、骨笼、鬼影或其他已否决方向回归。

## 6. Environment & Scene Direction

### 6.1 正常七中

- 教学楼首先是可以被玩家学会的空间：教室编号、楼梯方向、厕所位置、窗外参照和声音传播要相互支持。
- 正常一周和周末片段使用生活痕迹建立记忆点，为晚自习后的空间错位提供比较基准。
- 墙面磨损、粉笔灰、值日工具、公告和个人物品应有原因，不能只堆“恐怖旧物”。
- 原著锚点与项目原创空间必须分开标注；未核对的校舍细节不能伪装成原著事实。

### 6.2 鬼域中的七中

- 保持近处结构可信，通过远端缺失、路线重复、楼层关系错误和声音位置异常制造恐怖。
- 手机手电筒只揭示有限范围；玩家不应在近乎全黑时准确读出远处楼层和细节。
- 相同物理坐标的不同鬼域空间应保留一个共同构图锚点，再通过光、物件状态和人物缺席显示空间分离。
- 交互热点必须落在物理可信位置，并可通过键盘顺序访问。

### 6.3 场景构图

- 桌面画面以场景为最大视觉区域，档案和状态栏退居辅助位置。
- 每个画面只设一个主观察方向和少量有意义的交互物；密度来自信息关系，不来自图标数量。
- 长文本进入独立可读层，不直接覆盖关键环境。
- 环境图应为 16:9 或可安全裁切的宽幅构图，并预留文本与热点安全区。

## 7. UI / HUD Visual Direction

### 7.1 第一章学生阶段

- 主界面是现场，不是总部仪表盘。
- 可用媒介来自人物当前拥有的东西：手机、通话、手电、纸条、课本空白页和记忆。
- 操作用动词表达，例如“照向楼梯转角”“贴近门听”“回拨电话”，避免抽象的“调查 +1”。
- 规则推断应展示事实、来源和矛盾，不能直接替玩家自动拼出答案。

### 7.2 后续官方阶段

- 只有剧情确认主角进入官方体系后，才引入原创行动档案、事件编号和通讯界面。
- 官方感来自严谨的信息组织、权限层级和行动术语，不来自挪用原作官方 Logo 或商业作品素材。
- 原创标识使用项目自己的“缺口索引矩形”，配合 Revival Archives / 复苏档案字标；不得标成原著官方产品。

### 7.3 字体与图标

- 长正文优先系统中文无衬线字体栈，保证不同平台可读。
- 档案标题可使用系统宋体/衬线字体栈；等宽字体只用于编号、时间和机器记录。
- 最小常规正文目标为 16 CSS px；重要操作不低于 16 CSS px。
- 图标采用单色线性或实心几何符号，并始终配文字标签；不使用只靠神秘符号猜测的操作。

### 7.4 动效

- 动效只说明状态变化、空间关系或输入结果。
- 普通操作反馈 120–220 ms；场景转移可使用 300–700 ms 的受控过渡。
- 灵异异常可以出现一次错帧、偏移或亮度断层，但不循环播放。
- prefers-reduced-motion 下取消视差、抖动和长过渡，保留瞬时状态替代。

## 8. VFX, Audio-Visual Feedback & Asset Standards

### 8.1 VFX

- 优先使用局部遮罩、光照边界、细微位移和一次性状态变化。
- 禁止快速频闪、持续色差、全屏血污、无意义胶片噪点和高强度屏幕震动。
- 手电、电话失真、楼层错位和门后空间必须各有可辨识但克制的反馈语法。
- 视觉效果不能提前暴露尚未被玩家验证的规律。

### 8.2 资产格式与预算

| 类别 | 目标规格 | 格式 | 单资产建议预算 |
|---|---|---|---|
| 场景底图 | 1920×1080 工作尺寸，可安全裁切 | WebP/JPEG；透明时 PNG | 通常不超过 500 KB |
| 人物半身或局部 | 透明背景、按实际显示尺寸导出 | WebP/PNG | 通常不超过 250 KB |
| UI 图标 | 24/32/48 px 网格 | SVG 优先 | 通常不超过 20 KB |
| 局部效果贴图 | 2 的幂尺寸，避免超大透明画布 | WebP/PNG | 通常不超过 150 KB |
| 环境音 | 可循环时必须无爆点 | OGG/MP3 | 按场景延迟加载 |
| 短反馈音 | 短尾音、峰值受控 | OGG/MP3 | 通常不超过 100 KB |

以上是 Web 首版预算，不是画质承诺。Campaign 首屏压缩资源继续以 2 MB 内为目标，章节资产按场景加载。

### 8.3 命名与来源

- 文件名：category-subject-state-variant.ext，例如 scene-seven-high-west-stair-normal-v01.webp。
- 所有资产必须记录来源、作者/生成方式、许可和修改记录。
- AI 生成资产如被使用，必须经过人工修正和一致性检查，并保留生成来源记录。
- 不复制小说正文、官方 Logo、商业插画、影视截图或其他未授权素材。
- 玩家需要读取的文字保留为 HTML，不烘焙进场景图。

### 8.4 音画可访问性

- 关键声音线索必须有非听觉备份，但备份不能直接泄露答案。
- 音频默认可控，提供总音量、环境音和提示音控制；浏览器自动播放限制下不得让游戏流程失效。
- 所有热点可用键盘到达，焦点顺序遵循场景空间或阅读顺序。
- 缩放到 200% 时核心操作、正文与状态信息不得被裁切。

## 9. Reference Direction & Prohibitions

### 9.1 参考方向

| 参考 | 借鉴什么 | 明确不借鉴什么 |
|---|---|---|
| 中国普通公立学校的纪实摄影 | 日常光线、物件密度、校舍真实比例 | 不把“破旧”当成唯一恐怖标签 |
| 公共机构纸质档案与事故记录 | 信息层级、编号、来源和可信度表达 | 不仿制现实机关印章或原作官方 Logo |
| 《恐怖的世界》 | 让规则压力和信息判断成为恐怖主体 | 不复制黑白漫画风、版式或战斗结构 |
| 《隐形守护者》 | 人物选择和后果的清晰呈现 | 不把正式 Campaign 做成纯视频分支树 |
| 槐荫里 Prototype | Web 交互、冷档案、暗红危险语义的经验 | 不继承鬼影、门牌、七日结构和卡片化布局 |

### 9.2 禁止项

- 通用紫蓝科技渐变、霓虹 HUD 圆环和发光玻璃卡片；
- 全屏循环 glitch、扫描线、抖动或红闪；
- 为“有官方感”而使用未授权官方 Logo、角色立绘或宣传图；
- 把第一章学生阶段包装成已经拥有总部权限的负责人；
- 用发光描边替代场景构图和交互可读性；
- 把厉鬼画成等待被打掉血条的常规怪物；
- 提前为 OPEN / PAUSED 的第一只鬼、白月光异变或后期灵异拼图制作定稿；
- 让氛围层覆盖正文、焦点、字幕或必要空间线索。

## Lean Self-Review

- 九个生产部分均有可执行约束，不是情绪形容词合集。
- 视觉规则能直接排除“静态卡片论坛”“满屏故障”“官方素材挪用”等已知偏差。
- 第一章学生阶段与后续官方阶段明确分离，没有提前赋予主角总部身份。
- 第一只鬼和第五幕仍为 OPEN / PAUSED，没有通过美术设定偷偷补完剧情。
- 资产预算与当前 Web 技术偏好一致。
- 独立 Art Director gate 未运行；在 lean 流程中该门禁不是阶段阻塞项。
