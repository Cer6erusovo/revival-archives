# System GDD: First-Person Spatial Exploration

> Status: **WORKING — product direction LOCKED; detailed system design pending**
>
> Created: 2026-08-20
>
> Replaces: `spatial-scene-exploration.md` for the formal Campaign
>
> Scope: Formal Campaign only

## 1. Confirmed direction

正式 Campaign 使用第一人称 3D 连续空间。玩家在教室、走廊、楼梯和厕所中直接移动、转头、观察、靠近并操作实体，不再以固定 node 与离散 viewpoint 作为主要空间表现。

第一人称不是为了加入战斗或扩大地图，而是让以下信息自然存在于场景中：

- 自己与门、人物和出口的距离；
- 一扇门正在缓慢关闭还是已经接触门框；
- 锁舌是否开始动作、是否已经完全落下；
- 隔着门上玻璃能看见谁、还剩多少介入时间；
- 脚步、门轴、锁舌和求救声的方向与远近；
- 回头后空间、人物和物件是否仍与记忆一致。

## 2. Player fantasy

玩家应感到自己身处一段真实、可记忆的中国旧校舍，而不是在选择场景卡片。规律判断来自身体所在位置、视线和行动后果；玩家需要亲自决定先看哪扇门、跑向谁、是否把自己留在可能落锁的空间里。

## 3. Scope limits — LOCKED

- 不以枪械、近战、血条或反应闪避战斗为核心；
- 不做开放校园或无缝开放世界；
- 不为展示物理效果加入可搬动一切的沙盒；
- 不把大量 NPC、写实面部和复杂动作捕捉作为首个验证切片前提；
- 不把第一人称等同于持续冲刺或追逐游戏；
- 现有 Web Prototype 不迁入新工程，也不因转向而删除。

## 4. First feasibility slice — LOCKED scope

首个第一人称验证切片只包含：

- 一条旧校舍走廊；
- 两间教室；
- 一组厕所隔间；
- 至少一扇带玻璃观察窗的门；
- 一名门内受困者；
- 一次从未锁到开始关门、锁舌动作、完全落锁的连续过程；
- 手电、脚步、门轴、锁舌与受困者声音的基本空间反馈。

该切片不验证完整章节、驾驭鬼锁、白月光悲剧、复杂 NPC 群体或长期存档。

## 5. Acceptance questions

- 不使用“大字提示门要锁了”时，玩家能否注意到异常过程？
- 玩家能否通过门上玻璃、声音和距离理解谁处于危险中？
- 玩家能否明确区分“尚可介入”与“已经完成落锁”？
- 接近、拉门、呼救或其他动作是否有清楚而一致的现场反馈？
- 即使没有战斗，玩家是否会因空间距离和即将失去救援机会而紧张？
- 关闭头部晃动、动态模糊或声音后，必要信息是否仍然成立？

## 6. OPEN design work

- 基础移动速度、冲刺、蹲伏和碰撞边界；
- 交互射线、手部表现和门体物理采用动画还是受控状态机；
- 视野角、鼠标灵敏度、镜头晃动、动态模糊与晕动症设置；
- NPC 的最低动作与视线需求；
- 鬼锁选择、预警、救援和防御动作；
- 键鼠以外的输入范围；
- 首发桌面平台、性能目标和最低硬件；
- Godot 项目结构、脚本语言和具体渲染设置。

这些内容必须在对应 GDD / ADR 中确认后才能进入正式实现。
