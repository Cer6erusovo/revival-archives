## 1. 一句话概念

《复苏档案》是一款基于《神秘复苏》世界观的非商业单人 Web 规则调查与生存恐怖同人游戏：玩家扮演大昌市七中的一名普通学生，在灵异事件中观察、验证并利用厉鬼规律，同时承受驾驭厉鬼的代价，最终走出一条不依附于杨间的独立传奇。

## 2. 核心身份

| 项目 | 当前定义 |
|---|---|
| 类型 | 规则调查、生存恐怖、叙事成长 |
| 平台 | 桌面浏览器优先，可由 GitHub Pages 静态发布 |
| 受众 | 喜欢《神秘复苏》、规则推理、世界探索和长期养成的中文玩家 |
| 模式 | 单人 |
| 时长 | 章节制长期 Campaign；单章与总时长暂未锁定 |
| 发布 | 免费、非商业同人 |
| 制作约束 | 个人首次开发，以小而可验证的阶段逐步完成 |
| 体验参考 | 《恐怖的世界》的规则压力、《隐形守护者》的选择后果、《质量效应》的长期角色成长；不照搬其战斗或产品规模 |

## 3. 同人边界

- 本项目不是官方作品，不代表原作者或版权方。
- 不复制原著正文，不使用未经许可的官方 Logo、插画、音频或其他资产。
- 原创主角与杨间同校，但不会跟随杨间重走原著路线，也不会夺取杨间的关键功绩。
- 与原著人物和事件的交集应当稀少、克制，并服务于同一世界中“另一条传奇”的可信感。
- 原著事实与项目原创设定必须分别记录，不得把项目选择伪装成原著事实。

## 4. 核心幻想

玩家不是通过火力压制厉鬼，而是：

1. 进入一个规律尚不清楚的异常空间；
2. 观察环境、人物和异常反馈；
3. 区分事实、传言与错误推断；
4. 用有风险的行动验证规律；
5. 找到规则中的生路或漏洞；
6. 必要时动用自身灵异力量，并承担厉鬼复苏等代价；
7. 把经历转化为档案、关系与长期成长。

主角最终应具备达到顶级驭鬼者层级的潜力，但第一只鬼、完整灵异拼图和终局形态目前均为 OPEN，不在本文中补定。

## 5. 独特切入点

正式 Campaign 从原著七中敲门鬼事件开始，但视角位于杨间教室之外：

- 主角是杨间同校、另一间教室的普通学生；
- 同一场全校性灾难同时塑造两条不同的人生路线；
- 杨间获得鬼眼并开始他的传奇，主角则在另一条空间与关系链上求生；
- 不熟悉原著的玩家也应能理解当前危险，熟悉原著的玩家则能从时间和空间锚点中感到世界重合。

## 6. 体验结构（MDA）

MDA 在这里指“游戏机制带来什么行为，再让玩家产生什么感受”。

### 6.1 目标感受优先级

1. Discovery：通过观察发现隐藏规律；
2. Challenge：在信息不全和代价明确的情况下做选择；
3. Narrative：选择改变人物关系、事件结果与长期档案；
4. Fantasy：成为依靠规律、判断和代价活下来的驭鬼者；
5. Sensation：空间、声音、光线和界面共同制造压迫感；
6. Expression：玩家形成自己的调查方式与风险偏好。

Fellowship 和 Submission 不是当前核心目标：本作是单人体验，也不以无压力消遣为定位。

### 6.2 希望玩家形成的行为

- 先观察，再行动；
- 交叉核对线索，而不是相信第一段提示；
- 记住正常校园的空间与人物关系，用正常状态识别异常；
- 为保护特定人物承担风险，但无法保证所有人都得救；
- 失败后能从可观察的反馈中理解原因，而不是只看到突然死亡。

### 6.3 概念级机制

以下只是概念边界，详细规则应在 Systems Design 阶段单独锁定：

- 空间探索与可交互现场；
- 观察、假设、验证和后果反馈；
- 人物关系与事件后果状态；
- 厉鬼能力、复苏代价与成长拼图（当前 OPEN / PAUSED）；
- 档案、章节存档与失败信息保留。

## 7. 核心循环

### 7.1 每一步

查看现场 → 选择移动或交互 → 获得环境与声音反馈 → 更新判断 → 决定继续、撤退或冒险验证。

### 7.2 每个灵异事件

认识正常空间 → 异常侵入 → 收集事实 → 形成表层规律 → 承担风险验证 → 找到生路或付出代价 → 记录到档案。

### 7.3 每次游玩

完成一个可保存的场景片段或事件阶段，让人物状态、线索和后果能够在下次继续。

### 7.4 长期 Campaign

普通学生 → 经历七中事件 → 接触驭鬼者与官方体系 → 处理更多灵异事件 → 形成自己的灵异拼图 → 建立独立传奇。

具体章节数、升级节奏和终局仍为 OPEN。

## 8. 设计支柱

### 8.1 规律先于对抗

厉鬼无法用普通战斗逻辑消灭。理解触发条件、行动边界和规则漏洞，才是生存的主要手段。

### 8.2 力量必须有代价

灵异能力不是无成本技能树。越依赖厉鬼，越接近复苏或其他不可逆后果。

### 8.3 原创传奇与原著传奇并存

主角会听闻或偶遇原著事件，但必须拥有自己的案件、人物关系、损失和决定。

### 8.4 普通生活让恐怖有重量

校园、周末、同学与未说出口的感情不是过场装饰；先建立正常生活，异常侵入才真正可怕。

### 8.5 Web 端必须真正可交互

正式体验不能退化为静态论坛或卡片阅读。场景、行动、声音、状态和反馈必须让玩家感到自己在现场做决定。

### 8.6 非目标

- 不是以正面战斗为核心的动作 RPG；
- 不是 MMO 或无缝开放世界；
- 不是杨间队友模拟器；
- 不是无代价的超能力爽游；
- 不是只靠文字卡片推进的静态页面；
- 不以廉价跳吓或血腥堆砌替代规则恐怖。

### 8.7 Visual Identity Anchor

**视觉规则：先让校园、人物与调查工具像一个真实可用的中国日常世界，再让灵异只破坏其中一条可信的秩序。**

- 正常先可信：正常阶段优先建立可记忆的空间、人物和物件关系。
- 异常要局部而准确：用错位、缺失、重复或声音距离破坏一个具体事实，不用满屏故障代替恐怖。
- 现场先于界面：场景、声音和动作承担调查，UI 只负责操作、记录与复盘。
- 恐怖必须可读：危险可以不完整，但不能因画面过暗、动效过强或纯声音谜题变成随机失败。

完整视觉约束见 [art-bible.md](art-bible.md)。

## 9. 第一章边界

### 9.1 已锁定

第一章只锁定到以下位置：

~~~text
事件前一周普通校园生活
→ 美好周末
→ 周一晚自习
→ 周正进入杨间班
→ 鬼域侵蚀
→ 五楼逃亡
→ 腐朽楼板坍塌
→ 主角与杨间路线自然分离
→ 西楼梯不断向下
→ 主角与白月光都确认自己在“西楼梯”
→ 电话能够接通
→ 两人实际处于同一位置的两个不同鬼域空间
→ 主角推开旧后勤入口防火门，进入缺失楼层空间。
~~~

### 9.2 当前停止线

第一章场景与剧情正式暂停在第五幕入口。以下内容全部为 OPEN / PAUSED：

- 主角第一只鬼；
- 主角获得或驾驭它的方式；
- 主角继续前进的具体驱动力；
- 与白月光的重逢、失去或转折；
- 第五幕后续和第一章结局。

除非用户明确重开这一轮设计，不应继续创作或从旧候选中自动选定答案。

## 10. 槐荫里 Prototype 与正式 Campaign

槐荫里 Prototype 是已经可运行的早期交互试验，不是正式 Campaign 的序章。

### 10.1 可继承的经验

- 浏览器内场景与行动交互；
- 规则调查和状态反馈；
- 定性症状而非传统数值面板；
- 静态发布、自动测试和浏览器验证经验。

### 10.2 不自动继承的内容

- 鬼影设定；
- 门牌号主线；
- “七日限期”作为正式 Campaign 的全局结构；
- 开局已接入总部终端的身份；
- 现有 localStorage 存档结构。

当前不移动 src/，不改 Prototype 逻辑，也不迁移存档。正式 Campaign 未来应拥有独立入口、独立版本化存档和清晰的数据边界。

## 11. 目标玩家

| 玩家需要 | 本项目如何回应 |
|---|---|
| 熟悉原著时获得世界重合感 | 使用可靠的原著时间、空间和人物锚点 |
| 不熟悉原著也能进入故事 | 当前危险、人物关系和选择在游戏内自洽 |
| 喜欢推理 | 规律能通过行动验证，错误也有可解释反馈 |
| 喜欢成长 | 人物、档案、关系和灵异拼图跨章节积累 |
| 喜欢恐怖 | 用空间错位、声音、光线和代价制造持续压迫 |
| 只有碎片时间 | 章节内提供明确的场景片段和可恢复进度 |

## 12. 技术与发布边界

- Runtime：Web；
- 语言：TypeScript strict；
- 界面：语义化 HTML、CSS、DOM 优先；
- 发布：GitHub Pages 静态托管；
- 操作：鼠标与键盘均可完成核心流程；
- 表现：2D 原创界面、场景和音频，支持静音、音量控制与 reduced motion；
- 当前不依赖联网服务，也不承诺程序生成内容；
- 正式 Campaign 存档需要另行设计版本与迁移策略，不直接复用 Prototype 存档。

## 13. 主要风险与开放问题

### 13.1 风险

- 第一只鬼和第五幕暂停，使完整第一章与 Vertical Slice 暂时无法闭合；
- Web 交互容易退化为静态卡片，需要用实际浏览器路径持续验收；
- 长期养成容易产生能力膨胀，破坏规则恐怖；
- 原创能力和案件可能与原著原型碰撞；
- 白月光如果只作为奖励或惩罚，会削弱她作为独立人物的价值；
- 音画氛围、性能、可访问性和存档稳定性需要同时受到约束；
- 同人项目存在版权与下架风险，必须避免官方资产和正文复制；
- 个人首次开发，长期规模必须拆成小阶段，不能提前铺开后续章节。

### 13.2 开放问题

- 重开第一只鬼设计时，怎样用统一质量门槛淘汰“工具化、抽象化、漏洞化”的候选；
- 正式 Campaign 的场景结构、移动方式与调查界面；
- 失败、重试和永久档案信息之间的关系；
- 不使用简单好感度数值时，人物关系如何被玩家理解；
- 主角何时、以何种条件进入官方驭鬼者体系；
- Prototype 与 Campaign 的 URL、代码和存档最终如何隔离。

## 14. MVP 定义

MVP 在这里指“最小可验证版本”，用于验证核心体验，而不是把整章或整部游戏一次做完。

### 14.1 核心假设

即使没有传统战斗，Web 场景交互、空间记忆、可验证规律和清晰后果也能共同形成有压迫感的规则生存体验。

### 14.2 Campaign Concept Prototype

概念原型只需要验证：

- 一段可探索的正常校园，让玩家建立空间和人物记忆；
- 从异常侵入到旧后勤入口的已锁定第一至第四幕；
- 至少一条“观察 → 假设 → 冒险验证 → 明确后果”的完整循环；
- 可交互场景、动作、声音和状态反馈，而非静态卡片；
- 基础保存、重置、键盘操作和 reduced motion。

它不是完整第一章，也不是 Vertical Slice。

### 14.3 不属于本次 MVP

- 选定第一只鬼及其完整成长；
- 第五幕后续、白月光转折和第一章结局；
- 总部终端和完整官方体系；
- 第二章及后续案件；
- 迁移现有 Prototype 代码或存档；
- 完整商业级美术与音频资产。

### 14.4 阶段边界

| 阶段 | 目标 | 当前状态 |
|---|---|---|
| Concept Prototype | 正常校园片段 + 已锁定第一至第四幕，验证核心交互 | Systems Map 后再排期 |
| Vertical Slice | 完整第一章的代表性质量样片 | 被第五幕和第一只鬼阻塞 |
| Early Campaign | 多章成长与官方体系的初步闭环 | 后续 |
| Full Vision | 长期独立传奇 | 愿景，不作当前交付承诺 |
